1. Сервис **osago-aggregator** не будет иметь собственной базы данных. Будет предоставлять REST API для сервиса **core-app** с двумя ендпойнтами: 1) для запроса предложений по ОСАГО у страховых компаний по предоставленным данным; 2) для оформления ОСАГО в выбранной страховой компании.
Следует проанализировать возможность снижения нагрузки на сервис при переводе взаимодействия на GraphQL.

2. Сервис **osago-aggregator** способен к горизонтальному масштабированию в зависимости от нагрузки (метрика запросов на получение данных/оформление ОСАГО).

3. Сервис **osago-aggregator** при доступе к системам страховых компаний (СК) реализует паттерны Timeout (лимит ожидания ответа), Retry (повторный запрос), Circuit Breaker (временное исключение партнерской системы СК из запросов).

4. Сервис **osago-aggregator** даёт обратную связь в виде сообщений сервису **core-app** через брокер сообщений (Kafka): данные ответов по заявкам/ по оформлению от СК.

5. Сервис core-app обрабатывает события ответов от **osago-aggregator**. Инициирует события на основе SSE для предоставления информации **веб-приложению InsureTech** (информация о вариантах страховок, информация о необходимости оплаты, о заколючении договора). При оформлении страхового полиса ОСАГО вносит необходимые данные в базу.

6. Заявки на ОСАГО сервис core-app получает от **веб-приложения InsureTech** по протоколу REST API. Следует проанализировать возможность снижения нагрузки на сервис при переводе взаимодействия на GraphQL.
